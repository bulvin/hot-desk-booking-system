# Keycloak authentication requirements

- Use OAuth 2.0/OpenID Connect Authorization Code + PKCE. Keycloak owns credentials, confirmation, roles, sessions and issuance. The API accepts access tokens and issues none.
- Host registration, login, logout, names and password editing in Keycloak. Require confirmed email. Mailpit captures confirmation/resend locally.
- New users receive Employee; Administrator is explicitly assigned. Preserve booking authorization policies.
- Required names: maximum 50 characters each. Unique valid email: maximum 100. Password: minimum eight characters, upper/lowercase, digit and special character.
- Disable self-service email changes, password reset, implicit grants and application direct password grants.
- GET /api/profile returns authenticated identity, email, names, roles and confirmation. Remove custom account mutation/credential endpoints.
- Application handlers and the profile endpoint obtain authenticated identity and claims through IUserContext.GetCurrentUser(), returning ProfileDto. The scoped Infrastructure implementation snapshots subject, names, email, roles and confirmation once per request. No direct HttpContext access or claim parsing in handlers; unauthenticated or malformed user IDs preserve existing authentication errors.
- Validate signature, issuer, audience, expiry and confirmed email. Introspect on every authenticated request to reject terminated sessions immediately. Keycloak owns password-change session policy; administrators can terminate all sessions.
- Keep a local domain User with the Keycloak GUID as Id and first/last names. Keycloak owns credentials and account lifecycle. After successful token verification/introspection, create missing local users or update changed names through IUnitOfWork; unchanged names cause no save. Concurrent first requests must converge on the same user. Names reflect the latest token claims observed, not immediate provider changes. Reservation.UserId is a foreign key to User; ownership checks still use the authenticated subject. Administrator details show owner names from User; other users receive no owner data. Remove reservation name snapshots. Preserve all bookings and owner IDs through a backfill migration, including owners with no recorded names.
- Separate Keycloak and booking databases in the same existing PostgreSQL container. Preserve migration history and booking data. Legacy account/ownership import is excluded; do not silently relink or delete user data. Preserve any old Keycloak volume until its data has been explicitly migrated.
- Store API secrets in Web.Api .NET User Secrets, without .env files or helper scripts. Keep the existing read-only API mount. PostgreSQL uses postgres_password through POSTGRES_PASSWORD_FILE; Keycloak reads its configuration Docker Secret through --config-file. The confidential client credential from Keycloak must match the API's User Secret. Never log credentials or tokens. Public Swagger uses PKCE with explicit redirects/origins.
- No additional tests. Adapt existing tests and perform manual provider validation. Production TLS/SMTP, frontend, email changes, reset and legacy migration are deferred.
