# Keycloak authentication implementation plan

Supersedes local Identity following the approved move to Keycloak. The existing spec folder is retained for links.

1. Run Keycloak 26.7.5 with a separate keycloak database in the existing PostgreSQL container and data directory. Create the database once before starting Keycloak; do not add a second PostgreSQL container or volume. Import the hotdesk realm with public PKCE Swagger client, confidential API introspection client, Employee/Administrator roles, verified email and Mailpit SMTP. Disable application direct password grants, email changes and password reset.
2. Validate issuer, audience, signature, expiry and confirmed email in the resource API. Introspect every token for immediate current-session logout enforcement. Map the supported realm roles.
3. Add a minimal domain User with the Keycloak subject as Id and first/last names. Infrastructure synchronizes it after token verification/introspection, saves only missing or changed data through IUnitOfWork/IDateTimeProvider, and handles concurrent creation. Reservation stores UserId plus a User navigation, without name snapshots. DeskRepository loads the owner for administrator name display. Keep subject-based ownership checks and Mediator validation unchanged. Claims reflect the latest observed token; no provider lookup is needed for owner display.
4. Remove custom authentication services, Identity stores, local sessions, account handlers, SMTP sender and token issuer. Keep booking Mediator validation. Retain only GET /api/profile; account lifecycle happens in Keycloak.
   Expose authenticated claims through the single Application.Interfaces.IUserContext.GetCurrentUser() method returning ProfileDto, implemented as a scoped claim snapshot in Infrastructure. Booking handlers and the profile endpoint use it; remove HttpContextExtensions and direct handler dependencies on IHttpContextAccessor. Keep token validation in the authentication middleware.
5. Migrate directly from the original schema using KeycloakAuthentication, preserving Users and reservation ownership while removing local credentials and roles. Remove superseded IdentityAuthentication, KeycloakUserReferences, ReservationUserNames and LocalBookingUsers. Keep the current snapshot; use Web.Api startup configuration without a factory.
6. Configure Swagger Authorization Code + PKCE. Store API secrets in Web.Api .NET User Secrets, using the existing read-only mount. PostgreSQL uses the existing postgres_password Docker Secret. Keycloak reads an ignored configuration file mounted as a Docker Secret through --config-file. Copy the confidential client's Keycloak credential to the API User Secret. Use ordinary Docker Compose commands without helper scripts, .env files or host secret environment variables. Document realm persistence, hosted account operations and logout. Adapt existing tests without adding more tests. Verify real provider flow with disposable services.

Keycloak owns password-change session policy. Administrative global sign-out replaces custom all-session revocation logic. Frontend, production hosting, password reset and legacy account import remain deferred.
